GameDev Day 5

Posted on 2026-08-05 In Game , Wuxia

这几天的开发让我重新思考了一个问题：现在AI发展这么迅速，那么AI时代独立游戏开发者最重要的壁垒或者说独特性在于什么？

我所有对于Godot的使用都是Codex教我的，我写出来的bug也是Codex修复的，甚至Codex看不下去直接帮我写脚本。

正在消失的壁垒是什么：

  • 会写代码
  • 能快速画大量素材
  • 能做大地图、支线很多、结局很多
  • 有很多的钱很多的试错空间
  • 单纯依靠开发周期堆内容

最重要的壁垒，不是代码、美术资产数量，甚至也不是“会不会使用 AI”，而是：

能否持续做出一连串一致、克制、有个人判断的选择。

AI把“能不能做出来”变便宜了，却把“为什么值得存在”变得更贵。

仔细研究了下Steam的数据，仅 2025 年，SteamDB 就记录了超过 2 万款 Steam 新游戏。生产能力已经不再稀缺，真正稀缺的是玩家的注意力、信任和记忆。SteamDB 年度发行统计

所以，什么会是玩家真正认可的呢？像是星露谷物语，潜水员戴夫。

  1. 一句话就能说清楚的特性？
  2. 不断产生新选择的核心循环？
  3. 只有这位独立开发者会做出的取舍？
  4. 玩家能够产生自己的故事？
  5. 持续的迭代或者说DLC？

所以我的游戏壁垒应该是什么呢？

游戏系统阶段设计

Posted on 2026-07-31 In Game , Wuxia

在之前的游戏开发大纲中，写了游戏核心的一句话：

一个小人物，江湖生活的模拟游戏，玩家从一个小的练武档口开始，经营药田、炼制丹药，修炼武功、结交村民、探索秘境，建立门派，广收门徒，参加比武大会，逐步卷入江湖事件。

其实我想做的东西呢，比这个要多很多。单纯从游戏系统角度，按照阶段来说：

第一阶段

经营药田，或者炼丹，必须练功，领取任务/完成任务，每日循环。

第二阶段

增加武器

第三阶段

增加收徒，道侣

第四阶段

增加踢馆

第五阶段

武馆升级为门派，可以探索秘境

第六阶段

增加比武大会

目前想到的是这些后面想到的再补充更新了。

英雄坛说

Posted on 2026-07-31 In Game , Wuxia

高中的时候很想要一个文曲星，不是用来学习，是玩英雄坛说，包括后来的黄金英雄坛说，毕竟这是除了看小说之外唯一可以在课上娱乐的活动了。

所以当我想要做一个武侠类游戏的时候，我第一反应是参考英雄坛说，尤其是它的人物武功等级描述，当时张三丰/清虚道长的返璞归真给我留下了极深的印象。

英雄坛说真的是我觉得很厉害的一个武侠类游戏了。

一、八大门派

门派 主要特色 门派功法
太极门 重防御、借力反击，前期慢、后期强 太极拳、太极剑、玄虚刀法、太极神功、万流归一身法
八卦门 掌刀兼修，攻守均衡，比较适合新手 八卦游身掌、八阵八卦掌、八卦刀、混元一气功、游龙身法
雪山派 剑法攻击强、重敏捷，防御相对薄弱 入门十三式、雪山剑法、雪影擒拿手、雪山内功、踏雪无痕
花间派 只收女性，轻功和闪避突出，招式灵巧 一剪梅花手、柳叶刀法、花团鞭法、三花聚顶心法、飞蝶身法、驻颜术
伊贺谷 忍术、刀法与减益控制，变化诡异 无法拳、川枫一刀流、扶桑忍术、无影遁形身法
红莲教 高膂力、强攻击，拳杖为主，防御偏弱 太祖长拳、乱披风杖法、鹤翔身法、普天同济心法、红莲教义
兽王派 黄金版新增，动物拟形武功、变身和召鹰 五禽戏、赤尻连拳、猛虎拳、鹰爪功、鳄灵刀、龙象般若功、灵通心诀
茅山派 黄金版新增，独立法力体系，法术攻击强 天师掌法、灵符身法、谷衣心法、天师正道、万鸦咒、玄冰咒、五雷咒

名称上存在几组新旧写法：

  • 花团鞭法，也写作“花团锦簇鞭法”
  • 飞蝶身法，也写作“花飞蝶舞身法”
  • 鹰爪功，数据表中写作“鹰抓功”
  • 伊贺谷，部分旧攻略因字体或录入写成“尹贺谷”
  • 兽王派，少数资料写成“野兽派”

二、基础功法体系

所有门派都建立在基础武功之上：

  • 基本内功
  • 基本拳脚
  • 基本剑术
  • 基本刀法
  • 基本杖法
  • 基本鞭法
  • 基本轻功
  • 基本招架
  • 基本法术，主要供茅山使用
  • 读书写字
  • 驻颜术，实际上主要属于花间体系

游戏不是传统的“人物升级”，而是每门武功单独升级。学习消耗潜能，经验限制可学习上限；基本武功与门派武功共同构成实战能力。

三、代表性绝招

绝招不是独立功法等级，而是达到条件后，由相应武功发动。

  • 太极门：挤字诀、震字诀、乱环诀、阴阳诀、缠字诀、连字诀、三环套月
  • 八卦门：化掌为刀、刀影掌、八阵刀影掌
  • 雪山派：雪花六出、冰心诀、神倒鬼跌三连环
  • 花间派：柳浪闻莺、落英缤纷、三花
  • 伊贺谷：忍术烟幕、忍法影分身、旋风三连斩、迎风一刀斩
  • 红莲教：流星飞掷、雷动九天、红莲出世
  • 兽王派：变熊术、变鹰术、猛虎啸、飞鹰召唤
  • 茅山派：火焰弹、烈焰球、三昧火、火风暴；寒冰弹、雾棱镖、暴风雪、冰凌剑；闪光弹、雷火弹、掌心雷、连珠雷

四、武功等级称号

每提高5级更换一个评价；245级以后统一为“返璞归真”，255通常被视为数值极限。

没有一个抽象人物等级，而是拳、剑、轻功、内功、学识分别成长；最终形成的是一份个人武学履历，而不只是一串战斗力。

我决定我的习武两百年就用这套等级系统，太经典了。

开始！游戏开发大纲

Posted on 2026-07-30 In Game , Wuxia

纠结了很久，游戏名字就叫做： 习武两百年。

其他还有一个人的武林，人在江湖等等。

一个人从 0 做游戏，最重要的是别一上来“做完整游戏”，而是按 可验证的小版本 一层层长出来。我先按照下面的步骤进行，大部分的步骤是我十几年前的记忆，结合现在AI给我的推荐流程。

1. 定游戏一句话

先把游戏压成一句话：

一个小人物，江湖生活的模拟游戏，玩家从一个小的练武档口开始，经营药田、炼制丹药，修炼武功、结交村民、探索秘境，建立门派，广收门徒，参加比武大会，逐步卷入江湖事件。

这句话要回答：玩家是谁、每天做什么、长期目标是什么。

2. 定最小核心循环

不要先写世界观，先定玩家每天重复的玩法。

比如：

起床 -> 打理药田 -> 出门采集/接任务 -> 修炼/战斗 -> 交付任务/社交 -> 炼制丹药-> 回家睡觉结算

只要这个循环不好玩，后面加 100 个 NPC 也救不了。

3. 选引擎

目前看下来可以用的引擎：

  • Godot：轻量、免费、适合 2D、个人开发友好。
  • Unity：资源多、教程多，但项目管理和版本兼容更重。
  • GameMaker：做 2D 快，但扩展性不如前两者。
  • RPG Maker：适合剧情 RPG，不太适合复杂经营系统。

我自己选的话，选Godot。

按照四象限法则，应该对标星露谷物语，《星露谷物语》最初用的是 C# + Microsoft XNA Framework，并不是 Unity、Unreal 或 Godot。

更准确地说：

  • 早期版本：自研游戏框架/引擎 + C# + XNA
  • 后来更新：从 32-bit XNA 迁移到了 64-bit MonoGame
  • MonoGame 可以理解为 XNA 的开源继承者/兼容实现

我没有代码基础，直接Godot好了，不折腾，起码时间上能节省50%。

对比 MonoGame Godot
类型 C# 游戏框架 完整游戏引擎
编辑器 基本没有，要自己搭工具 自带编辑器、场景、动画、TileMap、UI
开发方式 几乎全靠代码 代码 + 可视化编辑
自由度 很高 高，但有引擎范式
上手速度 慢 快
适合人群 强程序员、想自研架构的人 独立开发者、想尽快做出游戏的人
做 2D 生活模拟 能做，但很多东西要自己造 很适合
Codex 辅助效果 能写代码，但工具链要你自己设计 更容易让 Codex 直接生成场景、脚本、系统

4. 做灰盒原型

先不做美术，反正也不会，最后用AI画？。用方块、占位图、简单 UI 做出：

  • 角色移动
  • 地图切换
  • 时间流逝
  • 体力系统
  • 背包
  • 物品拾取
  • 种植/浇水/收获
  • 睡觉进入第二天
  • 存档/读档

这一步目标不是好看，是证明“游戏能跑起来”。

5. 做第一个可玩日循环

让玩家能玩 3-5 个游戏日：

  • 种药草
  • 卖药草赚钱
  • 买种子
  • 和 2 个 NPC 对话
  • 接 1 个任务
  • 炼制丹药
  • 睡觉结算

做到这里，已经有游戏骨架了。

6. 搭数据系统

这一步很关键。不要把作物、NPC、任务全写死在代码里。

至少要数据化：

  • 物品表
  • 作物表
  • NPC 表
  • 对话表
  • 商店表
  • 任务表
  • 配方表
  • 地图入口表

可以用 JSON / CSV / ScriptableObject / Godot Resource。
以后新增“灵芝”“虎骨酒”“华山弟子任务”，应该主要改表，不改核心代码。
这让我想起了我之前做数值策划的日期，还有通过修改Plist玩Zombie Farm的日子。

7. 加核心内容系统

按优先级做（目前想到的，四象限法则，完全照搬《星露谷物语》）：

  1. 种植系统：播种、成长、季节、收获。
  2. 经济系统：出售、商店、价格。
  3. NPC 系统：日程、对话、好感、送礼。
  4. 任务系统：接取、目标检测、奖励、完成状态。
  5. 战斗/秘境：怪物、掉落、简单技能。
  6. 制作系统：炼药、烹饪、锻造。
  7. 节日/事件：特殊日期触发内容。

不要同时开太多坑。每个系统先做“能用版”。

8. 做垂直切片

垂直切片就是一小块“像正式游戏”的内容。

比如只做春季前 7 天：

  • 1 个村镇
  • 1 个家园
  • 1 个野外地图
  • 1 个秘境
  • 6 个 NPC
  • 10 个任务
  • 15 个物品
  • 5 种作物
  • 3 个敌人
  • 1 个小剧情结尾

这比做“完整大地图但全是空的”有价值得多。

9. 反复测试和删减

一个人开发最大的敌人是膨胀。

要不断问自己：

  • 这个系统真的服务核心循环吗？
  • 玩家 10 分钟内能感到成长吗？
  • 有没有太麻烦的操作？
  • 有没有内容做了但玩家根本不会看到？
  • 这个功能能不能以后再做？

删掉东西不是失败，是让游戏活下来。

10. 美术和音效逐步替换

前期可以用占位资源。等玩法成立后，再确定风格：

  • 俯视角像素风
  • 手绘 2D
  • 水墨武侠风
  • Q 版江湖风

一个人做，美术规格要克制。比如角色动画先做：

站立、走路、使用工具、攻击、受击

别一开始就做几十套动作。

11. 做正式 Demo

Demo 不需要大，但要完整：

  • 有开头
  • 有目标
  • 有成长
  • 有任务链
  • 有一个阶段性结局
  • 能存档
  • 没有明显崩溃
  • 新玩家不看说明也知道怎么玩

这时可以找 5-20 个玩家试玩。

12. 根据反馈扩内容

确认核心好玩后，再扩：

  • 更多 NPC
  • 更多季节
  • 更多作物
  • 更多武功
  • 更多秘境
  • 更多剧情线
  • 更多节日
  • 更多建筑升级

顺序是：系统先闭环，内容再扩张。

一个很现实的个人开发路线：

阶段 时间
